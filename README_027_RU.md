# SKERRY Engine 0.27.0 · предварительная сборка

**Создание проекта.** Для готового проекта нужен браузер с WebGL. Для сборки из исходников нужен Python 3.9+. Из распакованного каталога выполните команды ниже. Первая создаёт проект с исходным кодом, вторая встраивает локальные скрипты в переносимый HTML. Этот шаблон хранит текстуру в локальном скрипте и работает офлайн.

```sh
python skerry.py new MyWorld --template landscape
python skerry.py build MyWorld MyWorld-Play.html
```

Откройте MyWorld-Play.html. Команда python skerry.py new NewGame без параметра шаблона создаёт чистый проект с камерой, фиксированным шагом и пустой сценой. Для пустой сцены подключите только SkerrySDK.js. Этот файл включает JavaScript-рантайм, физику, рендерер, ECS, ввод, генератор и импорт моделей. Автодром, модели машин и карту Земли он не загружает.

```js
const game = new SKERRY.Game(canvas, {physicsHz: 120});
const world = game.world;
world.camera = SKERRY.basis([10, 65, 8], [0, 50, 0]);
const land = game.terrain({seed: 2026, size: 96, radius: 2, steps: 48});
game.start();
```

**Ресурсы и сцены.** Game.upload принимает геометрию, Game.load читает glTF 2.0 и GLB, Game.release освобождает полученные GPU-ресурсы. Для внешних ресурсов передайте читатель байтов. При смене сцены отсоедините её узлы перед освобождением. Game.dispose останавливает цикл, фоновые генераторы и освобождает ресурсы. Для перевозимого проекта можно использовать Game.loadScene. Аргумент read возвращает Promise с Uint8Array по пути от корня проекта. Чтение модели с одним путём выполняется один раз на загрузку сцены. Положение задаётся в метрах, rotation — единичный кватернион XYZW. После ошибки ранее открытая сцена остаётся доступной.

```js
const scene = await game.loadScene({
  format: "skerry.scene/1",
  nodes: [
    {id: "garage"},
    {id: "vehicle", parent: "garage", mesh: "models/vehicle.glb", position: [0, 0, 2]}
  ]
}, read);
scene.dispose();
```

**Генерация.** TerrainStream держит вокруг камеры квадрат (2 × radius + 1)² секторов. Центральный сектор имеет заданное разрешение, следующие кольца используют более редкую сетку. Высоты считаются на общей решётке, границы между LOD прикрываются юбками. Высоты и нормали считаются из одного массива выборок. При наличии Web Worker генератор передаёт готовые типизированные массивы в основной поток. Предусмотрен режим worker:false. При телепортации устаревший результат отбрасывается. Метод heightAt(x,z) возвращает высоту в метрах. Это запрос высоты для игровой логики. Контакты физического тела с таким рельефом проект задаёт отдельно. Для scatter передайте список объектов с parts, count, scale и необязательной функцией accept(x,y,z). Пример есть в examples/landscape/main.js.

**Расширение игры.** world.entities.create, set, get, query, remove и destroy работают с произвольными компонентами. world.systems — набор функций (dt, world), исполняемых на фиксированном шаге. Нужные системы подключаются кодом проекта. Частоту можно задать в диапазоне 1–1000 Гц. Длинные паузы ограничиваются 0,1 секунды догоняющей симуляции. Стоимость вычислений зависит от систем. Метод world.enablePhysics подключает решатель браузерной версии. Отдельный нативный полигон в полном архиве использует Jolt.

**Управление.** SKERRY.Actions переводит клавиши, оси, аналоговые кнопки стандартного геймпада и виртуальный ввод в именованные действия. Метод sample возвращает значения от −1 до 1. У виртуального ввода аргумент source позволяет разделять несколько касаний. Метод dispose освобождает слушателей событий.

**Рендер.** Для своих материалов задайте color, metal, rough и при необходимости emissive, coat и coatRough. Для четырёх ближайших точечных источников используются дальность, цвет, интенсивность и затухание по квадрату расстояния. Тени от солнца и карты нормалей входят в растровый путь. Рендерер отсекает ограничивающие объёмы мешей и групп экземпляров по камере отдельно в основном проходе и отражении. Тени используют собственный проход. Для подходящих по размеру текстур используются mip-уровни.

**Фото.** Откройте MaterialLab.html и нажмите кнопку расчёта. Для своего проекта создайте Game с photo:true *до* загрузки мешей. Метод game.photo({width,height,samples,bounces,seed}) возвращает RGBA8. Работает программный интегратор с деревом ограничивающих объёмов для каждой геометрии и вторым деревом для экземпляров. Он считает мягкость отражений по шероховатости, затенение прямого света и непрямой свет от вторичных лучей. Источники точечные или направленные, небо аналитическое. Используются непрозрачные и альфа-маскированные материалы, base color и metallic/roughness. Производительность и соответствие материалов растровому пути ограничены: отдельные шейдеры рельефа, смешанная прозрачность, экранные эффекты, отдельный лак и normal maps в этом интеграторе не реализованы. Фотопуть обслуживает объекты дерева GameNode, в том числе scatter. Аппаратные RT-блоки не используются.

**Что запускать.** examples/landscape — свой мир с процедурной растительностью и фоновой генерацией. MaterialLab.html — проверка материалов. Starter.html и PhysicsStarter.html демонстрируют работу SDK. В полном исходном архиве Skerry.html содержит прежние испытания, а native/project.godot — отдельный проект Godot 4.7.2 с Jolt. Из корня полного архива python build.py пересобирает рантайм и тестовые сцены. Команда node tests/engine27.cjs проверяет перенос буферов через рабочий поток, смену секторов, ECS, ввод, 120/240/1000 фиксированных шагов, манифесты и повторяемость фоторендера. Для других проверок запустите остальные tests/*.cjs.

**Границы выпуска.** Старшие целевые функции по 18 скриншотам перечислены в README_026_RU.md. В версии 0.27 добавлены универсальный ECS и ввод, генерация секторов и программный фотопуть. Открыты нативный аппаратный RT, mesh shaders, bindless и visibility/deferred pipeline, общий HLSL/Slang-путь, DLSS/XeSS, генерация кадров, сетевой модуль, полное покрытие Земли с геоданными и произвольное воксельное разрушение. Нужны испытания FPS, памяти, нагрева и стабильности на физических устройствах, включая Android, Windows и Apple. Результаты llvmpipe характеризуют программный рендерер. Коммерческая публикация и юридическая подготовка дистрибутива в эту сборку не входят.

**Нативный SDK.** Каталог native/addons/skerry можно перенести в свой проект Godot 4.7.2. Создайте Node3D со скриптом world_stream.gd, зарегистрируйте координаты сектора, путь к PackedScene и опциональную дальнюю модель через register_sector. На каждом физическом шаге передавайте update мировую позицию наблюдателя и скорость в метрах в секунду. Регулируются размер ячейки, радиус, упреждение и число одновременных чтений. При ошибке сектор сообщает sector_failed, повторное чтение разрешает retry_failed. Сценарий города использует этот же модуль.
